# RTC Service and Logging — Detailed Contracts

These project-specific contracts are intentionally documented separately from the general hardware rules. They originate from the supplied `CLAUDE.md`.

### Serial / I2C / RTC time
- Serial at 74880 baud for readable ESP8266 boot output.
- Initialize I2C early in `setup()` with explicit SDA/SCL pins before probing the RTC.
- `ClockApplication` owns `RtcService` from `rtc_ds3231.h` and injects it into the controller, display manager, and config API. Its state lives in members, with two file-static exceptions: the three `volatile` counters the SQW ISR writes, and the `loggingInstance` pointer used by the logging callback to access the application-owned service. The counters are genuinely singleton (one SQW pin) and kept out of the object so the `IRAM_ATTR` handler does not chase a pointer.
  - `RtcStatus` is a trivially-copyable POD with a fixed `char error[48]`, not a `String`. `getStatus()` is used as a cheap predicate (`isHealthy()`, the 2s health poll), and a `String` member would allocate and free on the heap on every call.
  - **The DS3231 holds UTC; local time is derived.** `setTimeZone(rule)` (called by `ClockController::applyConfig`) installs the parsed POSIX rule, and each accepted pulse converts the cached UTC second to local once, so the render path never converts and a DST change needs no write to the chip. Schema-1 configs (local-time RTC) are converted once at boot by `ClockApplication::migrateRtcToUtcIfNeeded()`, which saves the config **before** writing the chip so a failed save retries next boot instead of converting twice.
  - `begin()`, `getStatus()`, `getNow()` / `getUtcNow()` (live I2C reads: local and UTC), and `setUtc(utc, reason)` (also resyncs the cache; `reason` names the source in the log) provide device operations. **The live and cached reads all gate on `m_status.present`**; an ungated `m_rtc.now()` against a missing device returns BCD garbage, not a sentinel.
  - **`timeIsTrustworthy()` is not `isHealthy()`.** `isHealthy()` asks whether SQW pulses are arriving; after lost-power recovery the pulse train is perfectly healthy while the time itself is the firmware build date, which passes every range check and is still wrong by however long ago the image was built. `m_status.timeTrusted` is set when a chip answers with its own time, cleared by `recoverIfPowerWasLost()` and `flagInvalidTimeIfNeeded()`, and set again by `setUtc()`. **Anything that writes a timestamp to disk must consult `timeIsTrustworthy()`**, never `present` or `isHealthy()`.
  - SQW processing uses `beginSqwProcessing()` and `consumeSqwPulse(RtcTick&)`. The returned sample carries local time (`now`), the same instant as UTC seconds (`utc`), its ISR phase reference, and a discontinuity flag. A DST transition is not a discontinuity: UTC is continuous and only the local reading jumps.
  - RTC servicing owns the :00/:30 live-read resync, before schedules use the sample. Logging only prints at second zero. Pending count and latest edge are consumed together; backlogs, recovery, and corrected time jumps suppress past announcements. Stale queued edges wait for a fresh pulse; an edge during I2C defers resync to the next loop.
  - `getNowCached()` (local `DateTime`) and `getUtcCached()` (UTC seconds) provide second-resolution time at zero I2C cost while the cache is seeded and SQW is fresh, and are required on the display-render path. Before SQW processing or when pulses go stale, they fall back to live reads; a missing RTC returns the guarded fallback value without reading the bus.
  - **Two time scales, one rule.** Wall-clock rules and rendering are local: clock digits, Trading 09:30, Friday midnight, the sunset date, log timestamps, and the stored `countdown.end` / `countup.start` text. Everything measured as a duration is UTC: countdown/count-up anchors, blink windows, approach-alert targets, and live-crossing detection - so a DST change between now and a target neither adds nor removes an hour. Local becomes UTC only through `utcFromLocal()` (a skipped spring-forward time resolves forward; a repeated fall-back time resolves to its first occurrence).
  - `isHealthy()`: RTC present and SQW pulse arriving on schedule. Drives the "no rtc" overlay in `clock_application.cpp`.
  - `msIntoSecond(nowMs)` is clamped to 0-999 and phase-locked to the accepted ISR timestamp while SQW is fresh. If no pulse has been accepted or SQW is stale, the service deliberately falls back to `nowMs % 1000`. Renderers must call this method rather than compute their own phase.
- For fatal exception debugging, keep exception decoding enabled and include decoded stack traces in reports.

### Logging
- `log.h` provides `LOG_PRINTLN(msg)` and `LOG_PRINTF(fmt, ...)` macros.
- **A log line costs no I2C transaction and no heap allocation.** The timestamp comes from `RtcService`'s software cache via a static provider that never reads the chip; before the cache is seeded the logger prints `--:--:--` rather than falling back to a bus read. `RtcService::begin()` seeds the cache from the read it already performs, so boot lines still carry a real time. This matters because logging is the most frequent time consumer in the system, and it sits inside web handlers and the SQW consume path - the whole reason `getNowCached()` exists.
- Each line is prefixed with `logCurrentTime()`, the peak cont-stack usage in bytes (bare value, of 4096), and `logSourceName(__FILE__):__LINE__`.
- Both macros keep their strings in **flash** (`PSTR` + `Serial.printf_P`). On the ESP8266 a plain string literal occupies RAM for the life of the program; moving the log strings to flash is what holds static RAM under 50% (OTA headroom). Consequences:
  - `LOG_PRINTLN(msg)` and the `fmt` of `LOG_PRINTF` **must be string literals**. For a runtime string, use `LOG_PRINTF("%s", value)`.
  - `LOG_PRINTLN` pastes its literal into the printf format, so a literal `%` must be written `%%`.
- Each macro call emits exactly one line and appends the terminating newline itself, so **formats must not end with `\n`**.
- The same RAM rule covers HTTP replies: `HttpResponder::sendText`/`sendJsonError` take only `F("...")`, and literal `sendJson` bodies use its `F()` overload; the `const char*` `sendJson` is for bodies built at runtime.
